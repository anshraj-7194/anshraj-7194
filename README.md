## `> open_source_philosophy`

I build in public because software that compounds in value should compound in the open.

When developer tools are closed, knowledge silos form. When they're open, the entire ecosystem benefits — bugs get found faster, edge cases get covered, and the community shapes the product into something better than any single team could produce alone.

My principles when building open-source software:

- **Documentation is the product.** Undocumented software is incomplete software.
- **Defaults matter more than options.** A well-chosen default saves a thousand configuration decisions.
- **APIs are contracts.** Design them as if they will never change — because breaking them has a real cost.
- **Versioning is respect.** Respecting semver is respecting the developers who depend on your work.
- **Feedback loops must be short.** Great DX means developers find success in minutes, not hours.
